What the GDT does

Every memory access in protected mode goes through a segment register. The register holds a selector, which is an index into the GDT, not an address. Pick a selector and an offset, then step through what the CPU does with them.

    Each step shows one thing the CPU does. Checks marked "when the register is loaded" happen once, at mov ds, ax or a far jump. Checks marked "on every access" happen each time memory is touched.

    • The first three entries are the table built in src/gdt.c: a null entry, a ring 0 code segment and a ring 0 data segment, both with base 0 and a 4 GiB limit. That is the flat model: base + offset is just the offset, so segmentation changes nothing and paging does the protecting.
    • The fourth entry only exists when you tick the box. It shows what a segment with a non-zero base and a small limit would do, which is what Candidate B and L4's small address spaces would need.
    • Simplified: the CPU is at ring 0, there is no LDT, and a failed check is shown as a general protection fault (#GP). Our kernel has no IDT yet, so on the real machine that fault is currently a silent triple fault.
    • After this, with paging on, the linear address is translated once more into a physical address.
