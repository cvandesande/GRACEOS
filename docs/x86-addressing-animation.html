Why segment registers exist

A running program is made of three kinds of memory. The segment registers are how the CPU knows where each one is. Part 1 shows that in real mode, where the registers hold plain numbers. Part 2 shows protected mode, where the same registers hold tickets for a table the OS controls.

The words used here

code
The program's instructions.
data
Its variables and tables.
stack
Scratch space for function calls, local variables and return addresses.
CS
Code Segment: a register holding where the code starts.
DS
Data Segment: where the data starts.
SS
Stack Segment: where the stack starts.
ES, FS, GS
Spare segment registers (ES is used by string copies, FS and GS are free for the OS). Not used in this example.
offset
A distance from the start of a region. Instructions contain offsets, not full addresses.

  • The table in Part 2 is an example for one program, not the kernel's. The real one in src/gdt.c has only a null entry, one code entry and one data entry, and both have base 0 and a 4 GiB size. So in our kernel CS, DS and SS all point at one region that covers all of memory, and paging does the protecting instead.
  • Why still use segments at all in real mode: the 8086 had 16-bit registers, which reach only 64 KiB. Adding a segment start to a 16-bit offset let programs reach 1 MiB.
  • Simplified: DS is used for a read at the most privileged ring, there is no LDT, and a failed check is shown as a general protection fault (#GP). When the CPU loads DS it keeps a hidden copy of the table entry, which the GDT animation shows step by step.
  • In real mode the segment start is the register value times 16. That is why 0x2000 becomes 0x20000.
