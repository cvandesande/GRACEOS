How a 386 CPU works

Pre-reading for the GDT animations. No earlier knowledge of the CPU is assumed. Each part runs a tiny program one step at a time, so you can see what the CPU does and what changes. Press Step in each part; Play runs it for you.

The words used here

CPU
The chip that runs programs. It does one small thing at a time, very fast.
memory
A long row of numbered boxes outside the CPU, each holding one byte (a number from 0 to 255). The box number is its address. Both the program and its data live here.
instruction
One small step the CPU can do, such as "add 3 to this". In memory it is a few bytes.
register
A named storage slot inside the CPU. Registers are much faster than memory, and most work happens in them.
EAX, ECX, ESP...
The 386's 32-bit registers. A 32-bit register holds a number up to about 4 billion.
EIP
The instruction pointer: the address of the next instruction to run.
flag
A single yes-or-no bit the CPU sets after some instructions, for example "the last result was zero". The flags sit together in a register called EFLAGS.
stack
A region of memory used like a pile of plates: the CPU puts values on top and takes them back off.

Part 1: the CPU is a loop

The CPU repeats three things forever: fetch the instruction EIP points to, decode what it means, execute it. This program puts 5 in EAX, adds 3, and stores the result in memory.

Part 2: making decisions with flags and jumps

Normally EIP just moves to the next instruction. A jump changes EIP instead, and a conditional jump does so only if a flag says to. That is how loops and if-statements work. This program counts ECX down from 3.

Part 3: the stack

The stack is where the CPU keeps values it wants to get back later. ESP points at the top. It will matter again when we handle interrupts and faults, because the CPU saves where it was on the stack.

Part 4: where this leads to the GDT

Parts 1 to 3 treated an address as a single number. On the 386 it never is.

CR0 bit 0 = 0: real mode
The segment register is part of an address. No table, no checks. The CPU starts here at power-on.
CR0 bit 0 = 1: protected mode
The segment register is a ticket into a table, the GDT, that the OS fills in. The CPU checks every access against it.
  • A real 386 overlaps these stages: while one instruction executes it is already fetching and decoding the next. The animation shows the order in which things logically happen, not the timing.
  • The instruction bytes in Parts 1 to 3 are the real 32-bit x86 encodings of those instructions.
  • Numbers are stored low byte first (little-endian), so 5 appears in memory as 05 00 00 00. This is how x86 always works.
  • Only a handful of the CPU's registers appear here. The segment registers, CR0 and the GDT register are the ones the next pages are about.
